## Summary

Adds two opt-in built-in skills that form the **shipyard** delivery methodology, submitted per the #3879 maintainer disposition (opt-in contribution surface, no default-behavior change, narrowly specified contract). #3899 (minimal-code-discipline) was merged from the same campaign; these two skills complete that methodology's plan-to-ship half and its per-repo environment half.

- **`launch`** — governed delivery pipeline: mission brief → spec synthesis (C2) → vertical-slice tickets with blocking edges (C3) → frontier execution via team/serial (C4 batched async decisions) → verify + completion report (C5). Boundary rule: agents continuously run everything repeatable and acceptable-by-evidence; humans decide what cannot be judged or what fails expensively. Composes with existing lanes (deep-interview, execute, team, verify) — implements nothing they already do.
- **`drydock`** — per-repo harness scaffold: lays the 4-pillar shared environment (Context / Rules / Tools / Standards) across 5 surfaces (CLAUDE.md thin entry, CONTEXT.md glossary, docs/{adr,standards,business}, design-system, .omc/skills + .mcp.json + scripts), with `--check` drift audit and a legitimate no-UI skip branch.

Both are manual-invocation only: no keyword triggers, no prompt-ssot or role-projection changes, no `docs/CLAUDE.md` managed-block edits, nothing always-on.
